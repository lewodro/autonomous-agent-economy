FIELD NOTES · 03—05 OCT 2026 · BUILT IN PUBLIC

THE PROJECT,
BY THE COMMITS.

“I made agents fight until they were out.” This is the readable version of how that idea grew into a live Rust-backed game, an economy test bench, and a local MCP arena.

These notes group the major work already in Git. Each link opens the source commits; numbered ranges refer to the project’s development sequence, not product releases.

01

THE FIRST TABLE · 03 OCT

Make the game real before making it big.

The first commits set a simple rule: the simulation owns the result. Rust holds the match state, seeded randomness and turn rules. The first playable slice put small pixel agents around a shared table so a spectator could see what was happening without reading a wall of output.

That made the public idea concrete: agents take turns choosing how to survive, and the table keeps going until there is a winner, a draw, or a turn limit.

02

THE GAME GETS A MEMORY · COMMITS 021–040 · 03 OCT

Make decisions inspectable, not just animated.

The next run of work gave the engine typed events and versioned match records. The browser now renders those events instead of deciding what an attack, alliance or elimination means. Match turns gained revision checks, so stale or duplicate requests cannot quietly resolve the same turn twice.

Live spectators can follow a host-run match, reconnect after a refresh, inspect agents and watch on mobile. Optional HTTP model adapters received bounded requests and server-side credentials; deterministic mock strategies still work with no paid inference.

03

AN ECONOMY, WITH THE WALLS IN PLACE · COMMITS 041–068 · 03 OCT

Separate a game credit from actual money.

Economy work started with exact integer lamports, typed payment records and a lifecycle that rejects invalid transitions. Mock payment rails and escrow made entries, pots, winner payouts and refunds testable without a chain. Wallet identity, signing and payment behavior were split into separate interfaces.

The Devnet boundary was made explicit, and mainnet was rejected. A small lab and command-line demo exercise the same mock economy code. The browser game remains free unless a separate, explicitly configured economy path is being tested.

04

SURVIVE A RESTART · COMMITS 069–080 · 03 OCT

Do not lose the accounting when a process stops.

Payment intents, receipts and match snapshots became durable records. A trusted host attestation binds the finished Rust result to the match before settlement. For local testing, the backend can sign and verify actual transactions against a local Solana validator, then recover a submitted payout or refund after a simulated process crash.

This is a local test setup with backend-controlled test custody. It is evidence that restart recovery works in that environment, not a production custody service or a deployed smart contract.

05

PUT THE POT ON THE LIVE BOARD · COMMITS 081–089 · 03 OCT

Connect the economy to the match gate.

A funded match must verify every entry before the engine starts. The host scheduler, admission gate and economy event stream now share the same backend state. Spectators can see whether a pot is funding, locked, settling or complete, while the browser remains a display client.

Funding deadlines, bounded retries, cancellation and reconciliation were tested across process restarts. The free match path stays separate from funded mode.

GIVE THE ARENA MORE THAN ONE GAME · COMMITS 090–093 · 04 OCT

Add a second kind of contest, then prepare the site to travel.

The older Agent Arena gained verified tic-tac-toe alongside commit-reveal Rock Paper Scissors. In parallel, live match ownership, ongoing-game discovery and a Railway deployment path were hardened. Public payment modes became server capabilities rather than choices the browser could grant itself.

MAKE TEST-NET ACTIVITY VISIBLE · COMMITS 094–100 · 04 OCT

Show public addresses without calling test SOL “real stakes.”

A Devnet payment rail, test-wallet setup, visible agent addresses and Solscan links were added behind explicit test-SOL configuration. Creation limits and CI production checks put guardrails around that path. Devnet funds have no monetary value, and the complete public funded-match journey is still experimental.

No mainnet mode is available. The browser cannot enable funding by changing its own request.

09

LET PEOPLE BRING THEIR OWN MODELS · MCP · 05 OCT

Give an MCP host the seats; keep the rules in Rust.

The local MCP server can create arenas with 2–20 named identities, return each agent’s observation, accept one complete set of decisions for a turn, and expose the resulting public events. The person’s MCP host coordinates the models. The bridge does not call providers or hold their keys; Rust validates actions and decides the match.

The host session is saved locally so an arena can continue after the MCP process restarts. MCP arenas are free and local-only today: no wallet, funding or payout tool is exposed.

WHAT SHOULD COME NEXT?

Give agent identities a life between arenas.

The useful next step is a bring-your-own-agent match flow: save a public identity and strategy, connect it through a local MCP host, run a free arena, then compare its choices across matches. That makes the project interesting to spectators before anyone introduces money. Wallet rebirth and treasury support should follow only after the spending caps, custody authority and loss limits are concrete.
